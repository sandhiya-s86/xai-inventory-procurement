# Dataset Acquisition

## 1. Which dataset, and why

**Primary: UCI Online Retail II**
<https://archive.ics.uci.edu/dataset/502/online+retail+ii>

| Property | Value |
|---|---|
| Rows | 1,067,371 invoice lines |
| Period | 2009-12-01 → 2011-12-09 |
| Grain | One row per invoice line |
| Columns | Invoice, StockCode, Description, Quantity, InvoiceDate, Price, Customer ID, Country |
| Licence | CC BY 4.0 |
| Credentials | **None required** |
| Size | 45 MB (`.xlsx`, two sheets) |

### Why this one

1. **It is downloadable without credentials.** This was decisive. The
   alternative (below) needs a Kaggle account, acceptance of competition rules
   and an API token, none of which can be automated.
2. **It is real transactional data**, not a teaching toy. Gaps, duplicates,
   cancellations and service-line codes are all genuinely present, so the
   cleaning work in this project is real work.
3. **It contains real returns** (credit notes, 19,433 lines) and real
   intermittency (31.7% zero SKU-days), which makes both the preprocessing and
   the forecasting problem substantive rather than cosmetic.
4. **Two full years** span a complete seasonal cycle, which a chronological
   train/val/test split needs.

### Why not Corporación Favorita (the richer option)

The Kaggle *Store Sales — Time Series Forecasting* competition
(<https://www.kaggle.com/competitions/store-sales-time-series-forecasting>)
ships `train.csv`, `test.csv`, `stores.csv`, `oil.csv`, `holidays_events.csv`
and `transactions.csv`. That is genuinely richer: it has an `onpromotion`
column, daily oil prices, a holiday calendar and store metadata, all of which
would have made the EDA and feature engineering stronger.

It was rejected for one practical reason: **the Kaggle API returns HTTP 401
without a `kaggle.json` token**, and obtaining one requires a human to log in
and accept the competition rules. A project that cannot be reproduced by
running one command is worth less than a slightly thinner one that can.

Two consequences are carried honestly throughout:
- there is **no promotion flag**, so `price_discount_pct` (unit price against
  the SKU's own 28-day trailing median) is used as an explicit *proxy*;
- there is **no external regressor** such as oil price.

### What this dataset does NOT contain

This is the most important section of this document.

| Needed for procurement | Present? |
|---|---|
| Units sold, date, price, SKU, country | **Yes — real** |
| Stock on hand | **No — SIMULATED** |
| Suppliers | **No — SIMULATED** |
| Lead times | **No — SIMULATED** |
| Minimum order quantity, pack size | **No — SIMULATED** |
| Supplier capacity, reliability | **No — SIMULATED** |
| Purchase cost, holding cost, shortage cost | **No — SIMULATED** |
| Purchase orders | **No — SIMULATED** |

Everything in the right-hand "SIMULATED" rows is generated by `sim/` from
`sim/supply_config.yaml` under a fixed seed, and is labelled as simulated in
the code, the dashboard, the notebooks and the report. **No simulated value is
ever described as a measurement.**

## 2. How to download

### Automatic (recommended)

```bash
.venv\Scripts\python scripts\download_data.py
```

This fetches the archive over HTTPS, prints its SHA-256, extracts
`online_retail_II.xlsx` into `data/raw/online_retail/`, and verifies the file
landed. It never fabricates data: if the download fails it prints manual
instructions and exits non-zero.

### Manual fallback

1. Open <https://archive.ics.uci.edu/dataset/502/online+retail+ii>
2. Download `online+retail+ii.zip`
3. Extract `online_retail_II.xlsx` into `data/raw/online_retail/`
4. Verify: `.venv\Scripts\python scripts\prepare_data.py`

### Required vs optional files

| File | Required |
|---|---|
| `data/raw/online_retail/online_retail_II.xlsx` | **Required** — the only input |
| `online_retail_II.zip` | Optional — can be deleted after extraction |

There is **no credentials file to configure** for the primary dataset.

## 3. Verifying the download

```bash
.venv\Scripts\python scripts\prepare_data.py
```

Expect:

```
raw rows: 1,067,371  cols: 9
date range: 2009-12-01 07:45:00 -> 2011-12-09 12:50:00
kept 1,024,819 of 1,067,371 rows (96.01%)
200 SKUs x 604 trading days = 120,800 rows
```

`tests/test_data_quality.py::test_quality_report_exists_and_is_consistent`
asserts the raw row count equals 1,067,371, so a truncated or wrong file fails
the suite rather than silently producing different results.

## 4. Do not commit the data

`data/raw/`, `data/interim/`, `data/processed/`, `data/simulated/`,
`data/forecasts/` and `data/results/` are all git-ignored, as are `*.xlsx`,
`*.parquet` and `*.zip`.

Reasons: the raw file is 45 MB; the derived Parquet artefacts are regenerable
in minutes; and redistributing the dataset through a third-party repository is
not what the CC BY 4.0 attribution requirement is designed for. Clone the repo,
run `download_data.py`, run the pipeline.

---

## 5. Optional external validation — UCI Online Retail (2010–2011 subset)

The original *Online Retail* dataset (UCI id 352) is the 2010–2011 half of this
same business and is therefore **not** an independent validation set. It is not
used.

If genuine external validation is added later, it must come from a different
retail setting. That work is listed under future work in
`docs/pbl1_scope.md §2`, and would be run as a **separate** experiment — the
two datasets must never be merged into one training table, because they have
different SKU universes, currencies and trading calendars.
